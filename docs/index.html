How it works

Everything you need to trust an agent with real tools

Agentprobe sits between your agent and its tools. Your agent code doesn't change.

1

Record

Wrap your tools with probe.wrap(). Every call, argument, result and error becomes a trajectory you can inspect.

2

Break

Time out a tool, return garbage, or hide a prompt injection inside its output, with one line per fault.

3

Assert

Check the order of calls, forbidden tools, arguments and step limits, or require a pass rate over repeated runs.

4

Analyze

Keep run history, spot flaky tests, and watch trends in a dashboard that runs locally with one command.

Trajectory assertions

Assert on actions, not wording

An agent's reply changes on every run, so exact-match tests break. What matters is what it did.

  • Six chainable assertions for order, forbidden tools, arguments and limits
  • A failing test prints the agent's full step-by-step trajectory
  • Works with any tool-calling agent, scripted or LLM-driven
  • Says vs. does: catch a reply that claims something the agent never did
# the tool times out; the agent must not refund blindly
@pytest.mark.fault("lookup_order", "timeout")
def test_no_blind_refund_on_timeout(probe):
    my_agent("Refund order A123", probe.wrap(TOOLS))
    (probe.trajectory
        .called_after_success("lookup_order", "issue_refund")
        .called("escalate_to_human"))

Chaos for tools

Break your tools on purpose

Real tools time out, return junk, and carry text written by strangers. Test for that before production does.

  • Inject a fault into any tool, for every call or just the first
  • Hide the payload inside a field the agent already reads
  • Test indirect injection through web pages and live comments
timeout

The tool raises a timeout. Does the agent guess, or escalate?

server_error

An HTTP 500. Does it retry sensibly and stop?

malformed

Truncated JSON. Does it act on garbage?

empty

An empty result. Does it invent data to fill the gap?

prompt_injection

A hidden instruction in the output. Does it obey?

FAQ

Questions people ask

Short, honest answers.

Do I need an API key or an account?

No. Everything runs on your machine, including the real-model tests, which use a free local model through Ollama. The Claude and OpenAI examples need your own API key, and their tests skip when it's missing.

How is this different from tools that score answers?

Those judge the quality of what an agent says. Agentprobe asserts on what it does (which tools it called, in what order, with what arguments) and injects failures into those tools to see how the agent copes. The two approaches complement each other.

Which frameworks does it work with?

Any tool-calling agent, because you wrap the tools rather than the agent. There is a built-in adapter for MCP servers, and async tools are supported. It's a pytest plugin, so it runs in your existing CI.

Is the demo real?

Yes. Every run above is a recording of a real run. The real-model row is a small local model (qwen2.5:3b) at temperature 0, so it may behave differently on other runs. That variability is exactly what the repeat-run feature measures.

Is it on PyPI?

Not yet. Install it from source with the command at the top of this page. It is MIT licensed.
